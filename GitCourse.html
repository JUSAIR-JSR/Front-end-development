Working with Remote Repositories

Connect local repository to GitHub and sync changes

$ git remote add origin https://github.com/user/repo.git
# Connect to remote repository
$ git remote -v
origin https://github.com/user/repo.git (fetch)
origin https://github.com/user/repo.git (push)
$ git branch -M main
# Rename branch to main
$ git push -u origin main
Enumerating objects: 5, done.
Writing objects: 100% (5/5), 534 bytes | 534.00 KiB/s
To https://github.com/user/repo.git
* [new branch] main -> main
$ git pull origin main
# Get latest changes from remote
$ git fetch
# Download objects without merging

🔄 Push vs Pull

git push - Upload your commits to remote repository
git pull - Download and merge changes from remote
git fetch - Download changes without merging

Merging Branches

Combine changes from different branches

$ git checkout main
Switched to branch 'main'
$ git merge feature-login
Updating a1b2c3..d4e5f6
Fast-forward

|\

|/

🔄 Merge Types

Fast-forward merge - When no new changes on target branch
Three-way merge - Creates a merge commit when branches have diverged
--no-ff - Always create merge commit (recommended for feature branches)

    <h1>Welcome to My Site</h1>
=======
    <h1>Welcome to Our Awesome Site</h1>
    <nav>...</nav>
>>>>>>> feature-header
</header>
<<<<<<< HEAD - Your current changes

>>>>>>> feature-header - Incoming changes

Fork, Clone & Pull Requests

Contribute to open source projects and collaborate

🍴 Fork a Repository

1. Go to the repository on GitHub
2. Click the Fork button
3. This creates a copy in your account
4. You can now make changes freely

📥 Clone Your Fork

$ git clone https://github.com/your-username/repo.git
$ cd repo
$ git remote add upstream https://github.com/original-owner/repo.git
# Add original repo as upstream

🔄 Create Pull Request

1. Create a feature branch: git checkout -b feature-name
2. Make your changes and commit them
3. Push to your fork: git push origin feature-name
4. Go to your fork on GitHub
5. Click Compare & pull request
6. Add description and create PR
7. Wait for review and merge

🔄 Sync with Upstream

$ git fetch upstream
$ git checkout main
$ git merge upstream/main
$ git push origin main
# Now your fork is up to date

Advanced Git

Undoing Changes

Revert changes at different stages

↩️ Undo Unstaged Changes

$ git checkout -- file.txt
# Restore file to last commit state
$ git restore file.txt
# Newer way (Git 2.23+)
$ git restore .
# Restore all files

📦 Undo Staged Changes

$ git reset file.txt
# Unstage specific file
$ git reset
# Unstage all files
$ git restore --staged file.txt
# Newer way (Git 2.23+)

⏪ Undo Commits

$ git reset --soft HEAD~1
# Keep changes staged
$ git reset --mixed HEAD~1
# Keep changes unstaged (default)
$ git reset --hard HEAD~1
# Discard all changes (dangerous!)
$ git revert HEAD
# Create new commit that undoes changes

🔄 Reset vs Revert

git reset - Rewrites history (dangerous for shared branches)
git revert - Safe for shared branches, creates new commit
Use reset for local branches, personal work
Use revert for public branches, team work

.gitignore File

Ignore files that shouldn't be tracked

📝 Create .gitignore

$ touch .gitignore
$ # Edit the file with your rules
$ git add .gitignore
$ git commit -m "Add .gitignore"

📋 Common .gitignore Patterns

# Dependencies
node_modules/
vendor/
__pycache__/

# Build outputs
dist/
build/
*.exe
*.dll

# Environment variables
.env
.env.local

# Logs
*.log
logs/

# OS files
.DS_Store
Thumbs.db

# IDE files
.vscode/
.idea/
*.swp
*.swo

# Temporary files
*.tmp
*.temp

🎯 Pattern Rules

*.log - Ignore all .log files
!important.log - Except important.log
temp/ - Ignore entire directory
*.py[cod] - Ignore .pyc, .pyo, .pyd
**/__pycache__ - Recursive directory matching
file?.txt - Ignore file1.txt, file2.txt, etc.

⚠️ Remove Tracked Files

$ git rm --cached file.txt
# Stop tracking but keep locally
$ git rm -r --cached directory/
# Stop tracking directory
$ git commit -m "Stop tracking files"

Stashing Changes

Temporarily save work without committing

💾 Basic Stashing

$ git stash
Saved working directory and index state
# Stash all changes
$ git stash push -m "Work in progress"
# Stash with message
$ git stash list
stash@{0}: On main: Work in progress
stash@{1}: WIP on main: abc1234 Initial commit

📤 Applying Stashes

$ git stash apply
# Apply latest stash, keep in list
$ git stash pop
# Apply and remove from list
$ git stash apply stash@{1}
# Apply specific stash
$ git stash branch new-branch
# Create branch from stash

🗑️ Managing Stashes

$ git stash drop
# Delete latest stash
$ git stash drop stash@{1}
# Delete specific stash
$ git stash clear
# Delete all stashes
$ git stash show -p
# Show stash content as patch

🎯 Use Cases

Switching branches with uncommitted work
Emergency fixes on clean working directory
Testing changes without affecting current work
Temporary backups of work in progress

Git Workflow for Teams

Professional collaboration patterns

🌿 Branch Strategy

main/master
Production-ready code, always deployable
develop
Integration branch for features
feature/*
New features, bug fixes, experiments
release/*
Release preparation and testing
hotfix/*
Emergency production fixes

🔄 Feature Workflow

1. git checkout develop
2. git pull origin develop
3. git checkout -b feature/new-feature
4. Make changes and commit
5. git push origin feature/new-feature
6. Create Pull Request to develop
7. Code review and testing
8. Merge and delete feature branch

🏷️ Release Workflow

1. git checkout -b release/v1.2.0 develop
2. Update version numbers, changelog
3. Testing and bug fixes on release branch
4. git checkout main
5. git merge --no-ff release/v1.2.0
6. git tag -a v1.2.0 -m "Version 1.2.0"
7. git checkout develop
8. git merge --no-ff release/v1.2.0
9. Delete release branch

🚨 Hotfix Workflow

1. git checkout -b hotfix/urgent-fix main
2. Make emergency fix and commit
3. git checkout main
4. git merge --no-ff hotfix/urgent-fix
5. git tag -a v1.2.1 -m "Hotfix v1.2.1"
6. git checkout develop
7. git merge --no-ff hotfix/urgent-fix
8. Delete hotfix branch
